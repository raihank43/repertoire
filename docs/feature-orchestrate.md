## Description

The second resident and the repo's first **bundle**: a delegation-protocol skill plus the four agent definitions it requires (task-runner, task-reviewer, explorer, advisor), useless apart, installed together via the plugin. The main-chat model orchestrates and never delegates judgment: decomposition, briefs (GOAL/FILES/CONSTRAINTS/testable ACCEPTANCE CRITERIA), tier routing, and every verdict stay with it. Built and validated 2026-07-15→19 (smoke, sabotage, explorer fan-out, full-dress rehearsal, advisor PEER live run); migrated from five user-scoped files in `~/.claude/`.

### Revision 2026-07-27 — the `spiker` agent (5th bundle member)

_Forged 2026-07-27. Every choice below is user-confirmed except those marked **derived** — resolved from existing doctrine rather than interviewed, per forge's "explore instead of asking."_

- **Why it exists — the bundle *structurally excluded* spiking:** §2 demands testable ACCEPTANCE CRITERIA and §1 says do it yourself when you can't write one. A spike has no testable criterion up front — you don't know the answer yet — so investigation wasn't merely underused, it was **forbidden by contract**. The fix is a second brief shape, not encouragement. _(Rejected: treating it as a visibility problem and re-wording §1 to nudge runner use — the runner's contract cannot express a spike, so no amount of nudging reaches it.)_
- **Scope — empirical unknowns AND root-cause debugging.** Forward-looking ("will this approach work?", "how does this API actually behave?") and backward-looking ("why is this failing?") share one contract: a question, an exit condition, a finding as the deliverable, throwaway probes as the means. Debugging is the most common not-knowing task in real work, so including it is what keeps the agent from withering. _(Rejected: unknowns-only — narrower demand, high risk of never being reached for; external-behavior probes only — too thin to justify a bundle slot.)_
- **Chesterton's fence — this partially reopens shelved `debug-to-gotcha`, deliberately.** What got shelved 2026-07-19 was the **doc-writing ritual** (workflow-shaped, overlapping growing-docs' already-mandated gotcha capture). The **investigation half** was never the problem, and it's contract-identical to a spike. The spiker absorbs the investigation; the orchestrator still owns the doc write via `## Ending`, so the ritual stays shelved. BACKLOG's entry is annotated accordingly.
- **Isolation — main tree, scratch-scoped; `isolation: "worktree"` opt-in per brief.** The spiker runs in the real tree so deps, env, and the actual broken state work; it writes probes only to a gitignored scratch dir and removes what it created (Invariant #1 governs: delete only self-created paths). The orchestrator adds worktree isolation per-brief when a probe is genuinely destructive — migrations, dependency upgrades, destructive refactors — keeping the isolation call with the orchestrator, mirroring how §3 already treats worktrees as a conditional. _(Rejected: always-worktree — a fresh worktree is a clean checkout with no `node_modules`/venv/`.env`/build artifacts, so it frequently can't run the project at all, and a state-dependent bug won't reproduce in a pristine copy. Rejected: read-only + Bash — consistent with the other read-only agents but removes the ability to build a probe harness or add temporary logging, which is most of the value.)_
- **Stopping contract — `QUESTION / CONTEXT / EXIT CONDITION / BUDGET`** replaces GOAL/FILES/CONSTRAINTS/ACCEPTANCE for this tier. The orchestrator writes a semantic stop ("stop when you can answer yes-or-no with citable evidence") *and* a hard leash (~30 tool calls). Both, because this repo has the scar: explorer's recorded gotcha is haiku blowing past "sample a few" into a 42-call, 8-minute sweep — and a spike is more open-ended than retrieval. _(Rejected: budget only — without a semantic exit the agent doesn't know what "answered" means and spends the full budget every time. Rejected: exit condition with no cap — contradicts the leash discipline the explorer incident already forced on this repo.)_
- **Verdict vocabulary — `GREEN | RED | INCONCLUSIVE`.** GREEN/RED is reused, not coined: it's already the project's spike vocabulary (`_feature-template.md`'s Spike findings format, this doc's own 2026-07-19 finding). **INCONCLUSIVE is load-bearing** — "I proved it doesn't work" and "I ran out of budget" must never collapse into one word, or an architecture decision gets made on a false RED. _(Derived — pattern-matched to the roster's existing verdict shapes; the INCONCLUSIVE split was stated, not interviewed.)_
- **Model — `sonnet` default, `model:` override per brief.** Matches task-runner, the other write-capable agent. Rationale worth keeping: **reality corrects the spiker's hypotheses**, so it needs less raw reasoning than the advisor, which is pure reasoning against no ground truth. The override handles conceptually-hard-not-empirical unknowns; §5's SUPERVISOR advisor override is the existing precedent for per-brief model choice. Cheap enough to actually reach for — which was the original complaint. _(Rejected: opus+high — best hypothesis quality but prices the agent out of casual use, reproducing the very under-use it exists to fix. Rejected: sonnet with no override — gives up the escape hatch when probing can't rescue a bad hypothesis.)_
- **§1 triage fix — split ambiguity from uncertainty.** As written, §1's "handle it YOURSELF when the task is: ambiguous" would have swallowed every spike, killing the tier on arrival exactly as the acceptance-criteria clause did. Amend at the root: **ambiguous about what the *user wants* → handle yourself** (that's a conversation, not an investigation); **uncertain about what's *true* → spike it** (reality can answer, and it answers cheaper to a delegate). Sharpens §1 generally and gives a one-second routing test. _(Rejected: an exception carve-out — exception lists read as afterthoughts and leave two kinds of not-knowing conflated in the prompt. Rejected: leaving §1 alone — a live contradiction resolves toward the older, more established sentence, which is how spiking got excluded in the first place.)_
- **No reviewer gate; orchestrator-only spawn.** `task-reviewer` checks work against acceptance criteria, which a spike structurally lacks — so it can't review one; the orchestrator judges findings itself, as with explorer, and a contested high-stakes finding goes to the advisor. The runner↔explorer two-level hop stays retrieval-only: §1 justifies it as "retrieval briefs are hard to garble," and investigation briefs are the opposite; a runner hitting an unknown already has the right instruction — stop and report the blocker. _(**Derived** from existing doctrine, not interviewed.)_
- **Name — `spiker`.** Chosen for vocabulary coherence: the docs tree already speaks "spike" everywhere (`## Spike findings` in the template, `/forge`'s spike offer, this doc's own finding), so the agent name matches its output section — one word per concept. Accepts a widened sense of "spike" = any empirical investigation, forward or backward looking. _(Rejected: `investigator` — covers the widened scope more honestly but splits the vocabulary against a section called "Spike findings". Rejected: `prober` — coins a term the docs don't use anywhere.)_
- **The E2E-tester half of the pitch — cut, replaced by a §1 wording fix.** No sixth agent; instead §1's routing table names "writing or running test suites" explicitly as task-runner work. E2E testing already fits the existing brief contract *perfectly* — it has deterministic acceptance ("suite green"), which is precisely what a spike lacks. Under-use is a routing-visibility problem, and minimalism doctrine says fix it with words before adding a resident. _(Rejected: a dedicated tester agent — contract-identical to task-runner, so a near-duplicate that invites muddled briefs. Rejected: folding testing into the spiker — merges opposite contracts in one agent, which drifts toward whichever half gets used more.)_
- **Report format** (**derived** — follows the roster pattern): `1. VERDICT: GREEN | RED | INCONCLUSIVE` · `2. FINDING` (the answer, one paragraph) · `3. EVIDENCE` (what was actually run and observed — commands, outputs, file:line) · `4. CONFIDENCE + WHAT I DIDN'T TEST` (the negative space, mirroring explorer's "report what ISN'T there") · `5. CLEANUP` (scratch artifacts created and removed — makes Invariant #1 compliance auditable) · `6. RECOMMENDED NEXT` (options, never a decision — judgment stays with the orchestrator).
- **Packaging — a 5th agent in the existing bundle, not a new resident** (**derived**): RULES' Glossary defines a bundle as "a skill plus the agent definitions it requires," and ARCHITECTURE has no shape for a standalone agent. Ships as `plugins/repertoire/agents/spiker.md`; **minor** version bump to **1.1.0** per RULES §Versioning ("new or changed resident").
