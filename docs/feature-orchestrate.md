## Description

The second resident and the repo's first **bundle**: a delegation-protocol skill plus the six agent definitions it requires (task-runner, task-reviewer, explorer, advisor, spiker, librarian), useless apart, installed together via the plugin. The main-chat model orchestrates and never delegates judgment: decomposition, briefs (GOAL/FILES/CONSTRAINTS/testable ACCEPTANCE CRITERIA), tier routing, and every verdict stay with it. Built and validated 2026-07-15→19 (smoke, sabotage, explorer fan-out, full-dress rehearsal, advisor PEER live run); migrated from five user-scoped files in `~/.claude/`.

## Decided design

_Forged 2026-07-19 (model pins, invocation, ending, supervisor-validation path user-confirmed; bundle layout derived from ARCHITECTURE)._

- **Model pins — keep alias pins (`haiku`/`sonnet`/`opus` + `reasoningEffort: high`), genericize the brain-tag:** official aliases resolve on any machine and *are* the tier design (cheap scout / mid worker / high-reasoning gates). The skill's SUPERVISOR example drops this machine's `[brain:...]` tag for a generic "spawn with a `model:` override". _(Rejected: strip pins and document intended tiers — an explorer inheriting the session model silently burns the economics the design exists for.)_ **Amended 2026-07-28 — see Roster (below); the alias-only rule survives, the tier assignments were re-pinned once `reasoningEffort` was known to take five values.**

### Roster (re-pinned 2026-07-28)

Assumes an orchestrator at **Opus 5 @ medium** — the user's daily driver. The governing principle is **inverse effort**: *buy capability back on cheap models with effort; save cost on expensive models by spending less of it.* Read the table as pairs, never as model names alone.

| Agent | Model | Effort | Why |
|---|---|---|---|
| `explorer` | haiku | `max` | Fan-out economics are the whole point, so the model stays cheap. Max effort is a **new rung on the cheap-model escalation ladder** (previously: harder wording → tool budget → model bump) that didn't exist when that ladder was written, because the field's value domain was unknown. Buys leash-adherence without surrendering parallel-fire cost. |
| `librarian` | sonnet | `high` | Lookup over a known corpus; growing-docs makes relevance mechanical, so the work is careful reading rather than reasoning. |
| `spiker` | opus | `medium` | Promoted from `sonnet` + per-brief override — both real spikes turned out meaty enough that the override was the norm, so the default should say so. |
| `task-runner` | opus | `low` | Opus for instruction-following, low effort because this is the bulk-token role and the brief already contains the thinking. |
| `task-reviewer` | opus | *(unset)* | Deliberately carries **no** effort pin — inherits the session default. Sits above the runner on model, and the gate's value has been in scrutiny rather than depth (its one proven catch was a false self-report, not a hard inference). |
| `advisor` | **fable** | `high` | The one non-Opus judgment seat: a genuinely different model is what "fresh eyes" is buying. Override to `opus` per spawn when fable isn't wanted — that alias *is* in the spawn-time enum. |

Two consequences worth holding onto:

- **Model pins are soft; effort pins are hard.** The spawn-time override takes a `model:` (aliases only — `sonnet`/`opus`/`haiku`/`fable`) but has **no effort parameter**. So a wrong model is recoverable mid-session and a wrong effort is not — which is why the effort values got the argument and the model values didn't. _(Rejected: pinning `claude-opus-4-8` on the spiker — version-shaped names do resolve in frontmatter, but not in the spawn-time enum, so it can't be expressed as a per-brief override the way the original plan assumed; and a published plugin shouldn't pin a model an installer may lack. Loud failure, not silent — but still failure.)_
- **A wrong effort value is silent.** `reasoningEffort: banana` runs clean; a bogus `model:` errors loudly. Opposite typo behavior on two adjacent lines — hence the RULES proofread rule now covers all three fields.

_(Rejected: `explorer` at sonnet + xhigh — inverts the design. Explorer is the highest-multiplicity agent and its contract forbids interpretation ("no opinions, no synthesis"), so effort spent there buys deliberation the prompt then prohibits, while the model cost multiplies across every parallel fan-out. It would also have falsified every "cheap"/"haiku" reference in SKILL.md and the agent's own description.)_
_(Rejected: `task-reviewer` at opus + medium — an explicit downgrade from `high` that would have left the gate one rung above the thing it gates.)_
- **Invocation — user-invoked (`disable-model-invocation: true`),** confirming the logged 2026-07-19 decision: doctrine, not caution. Delegation is a 10–30× token loss below ~5 min of mechanical work; the human decides when the protocol runs. _(Rejected: model-invocation with triage as the only guard — re-opens a logged decision with no what-changed.)_
- **`## Ending` — selective, verdict-worthy only:** in a growing-docs host, a reviewer-caught defect → the touched feature doc's Gotchas; an advisor recommendation that decided something → PLAN's Decisions log including its would-change-my-mind condition as the revisit trigger. Routine PASS rounds and briefs stay in chat; elsewhere, §4's plain-prose batch report is the fallback. _(Rejected: log every batch — bulk mechanical churn flooding the docs is exactly the doc-theater failure mode.)_
- **SUPERVISOR mode — validated before shipping** (user chose validate-now over ship-experimental): staged a real run this session on a genuine decision (P3 triage order). See Spike findings. _(Rejected: ship-marked-experimental — user wanted the gap closed; strip-from-published — published/local divergence is the two-copies drift the cutover exists to prevent.)_
- **Bundle layout — per ARCHITECTURE:** `skills/orchestrate/SKILL.md` + the four defs in `agents/`, cross-referenced in both directions (SKILL.md names its agents; each agent's description says "spawned by the orchestrate skill"). Pitch sub-question 1 resolved by the existing layout decision — no new folder convention needed.
- **Cutover — same as minimalism:** delete the five local `~/.claude/` originals after the plugin version verifies in-session, with explicit user go-ahead.
- **Provenance — original** (no block; README says `original`). The tiered-orchestration post that inspired-then-got-rejected is credited in the pitch's evidence trail, not in the artifact.

### Revision 2026-07-27 — the `spiker` agent (5th bundle member)

_Forged 2026-07-27. Every choice below is user-confirmed except those marked **derived** — resolved from existing doctrine rather than interviewed, per forge's "explore instead of asking."_

- **Why it exists — the bundle *structurally excluded* spiking:** §2 demands testable ACCEPTANCE CRITERIA and §1 says do it yourself when you can't write one. A spike has no testable criterion up front — you don't know the answer yet — so investigation wasn't merely underused, it was **forbidden by contract**. The fix is a second brief shape, not encouragement. _(Rejected: treating it as a visibility problem and re-wording §1 to nudge runner use — the runner's contract cannot express a spike, so no amount of nudging reaches it.)_
- **Scope — empirical unknowns AND root-cause debugging.** Forward-looking ("will this approach work?", "how does this API actually behave?") and backward-looking ("why is this failing?") share one contract: a question, an exit condition, a finding as the deliverable, throwaway probes as the means. Debugging is the most common not-knowing task in real work, so including it is what keeps the agent from withering. _(Rejected: unknowns-only — narrower demand, high risk of never being reached for; external-behavior probes only — too thin to justify a bundle slot.)_
- **Chesterton's fence — this partially reopens shelved `debug-to-gotcha`, deliberately.** What got shelved 2026-07-19 was the **doc-writing ritual** (workflow-shaped, overlapping growing-docs' already-mandated gotcha capture). The **investigation half** was never the problem, and it's contract-identical to a spike. The spiker absorbs the investigation; the orchestrator still owns the doc write via `## Ending`, so the ritual stays shelved. BACKLOG's entry is annotated accordingly.
- **Isolation — main tree, scratch-scoped; `isolation: "worktree"` opt-in per brief.** The spiker runs in the real tree so deps, env, and the actual broken state work; it writes probes only to a gitignored scratch dir and removes what it created (Invariant #1 governs: delete only self-created paths). The orchestrator adds worktree isolation per-brief when a probe is genuinely destructive — migrations, dependency upgrades, destructive refactors — keeping the isolation call with the orchestrator, mirroring how §3 already treats worktrees as a conditional. _(Rejected: always-worktree — a fresh worktree is a clean checkout with no `node_modules`/venv/`.env`/build artifacts, so it frequently can't run the project at all, and a state-dependent bug won't reproduce in a pristine copy. Rejected: read-only + Bash — consistent with the other read-only agents but removes the ability to build a probe harness or add temporary logging, which is most of the value.)_
- **Stopping contract — `QUESTION / CONTEXT / EXIT CONDITION / BUDGET`** replaces GOAL/FILES/CONSTRAINTS/ACCEPTANCE for this tier. The orchestrator writes a semantic stop ("stop when you can answer yes-or-no with citable evidence") *and* a hard leash (~30 tool calls). Both, because this repo has the scar: explorer's recorded gotcha is haiku blowing past "sample a few" into a 42-call, 8-minute sweep — and a spike is more open-ended than retrieval. _(Rejected: budget only — without a semantic exit the agent doesn't know what "answered" means and spends the full budget every time. Rejected: exit condition with no cap — contradicts the leash discipline the explorer incident already forced on this repo.)_
- **Verdict vocabulary — `GREEN | RED | INCONCLUSIVE`.** GREEN/RED is reused, not coined: it's already the project's spike vocabulary (`_feature-template.md`'s Spike findings format, this doc's own 2026-07-19 finding). **INCONCLUSIVE is load-bearing** — "I proved it doesn't work" and "I ran out of budget" must never collapse into one word, or an architecture decision gets made on a false RED. _(Derived — pattern-matched to the roster's existing verdict shapes; the INCONCLUSIVE split was stated, not interviewed.)_
- **Model — `sonnet` default, `model:` override per brief.** Matches task-runner, the other write-capable agent. Rationale worth keeping: **reality corrects the spiker's hypotheses**, so it needs less raw reasoning than the advisor, which is pure reasoning against no ground truth. The override handles conceptually-hard-not-empirical unknowns; §5's SUPERVISOR advisor override is the existing precedent for per-brief model choice. Cheap enough to actually reach for — which was the original complaint. _(Rejected: opus+high — best hypothesis quality but prices the agent out of casual use, reproducing the very under-use it exists to fix. Rejected: sonnet with no override — gives up the escape hatch when probing can't rescue a bad hypothesis.)_
- **§1 triage fix — split ambiguity from uncertainty.** As written, §1's "handle it YOURSELF when the task is: ambiguous" would have swallowed every spike, killing the tier on arrival exactly as the acceptance-criteria clause did. Amend at the root: **ambiguous about what the *user wants* → handle yourself** (that's a conversation, not an investigation); **uncertain about what's *true* → spike it** (reality can answer, and it answers cheaper to a delegate). Sharpens §1 generally and gives a one-second routing test. _(Rejected: an exception carve-out — exception lists read as afterthoughts and leave two kinds of not-knowing conflated in the prompt. Rejected: leaving §1 alone — a live contradiction resolves toward the older, more established sentence, which is how spiking got excluded in the first place.)_
- **No reviewer gate; orchestrator-only spawn.** `task-reviewer` checks work against acceptance criteria, which a spike structurally lacks — so it can't review one; the orchestrator judges findings itself, as with explorer, and a contested high-stakes finding goes to the advisor. The runner↔explorer two-level hop stays retrieval-only: §1 justifies it as "retrieval briefs are hard to garble," and investigation briefs are the opposite; a runner hitting an unknown already has the right instruction — stop and report the blocker. _(**Derived** from existing doctrine, not interviewed.)_
- **Name — `spiker`.** Chosen for vocabulary coherence: the docs tree already speaks "spike" everywhere (`## Spike findings` in the template, `/forge`'s spike offer, this doc's own finding), so the agent name matches its output section — one word per concept. Accepts a widened sense of "spike" = any empirical investigation, forward or backward looking. _(Rejected: `investigator` — covers the widened scope more honestly but splits the vocabulary against a section called "Spike findings". Rejected: `prober` — coins a term the docs don't use anywhere.)_
- **The E2E-tester half of the pitch — cut, replaced by a §1 wording fix.** No sixth agent; instead §1's routing table names "writing or running test suites" explicitly as task-runner work. E2E testing already fits the existing brief contract *perfectly* — it has deterministic acceptance ("suite green"), which is precisely what a spike lacks. Under-use is a routing-visibility problem, and minimalism doctrine says fix it with words before adding a resident. _(Rejected: a dedicated tester agent — contract-identical to task-runner, so a near-duplicate that invites muddled briefs. Rejected: folding testing into the spiker — merges opposite contracts in one agent, which drifts toward whichever half gets used more.)_
- **Report format** (**derived** — follows the roster pattern): `1. VERDICT: GREEN | RED | INCONCLUSIVE` · `2. FINDING` (the answer, one paragraph) · `3. EVIDENCE` (what was actually run and observed — commands, outputs, file:line) · `4. CONFIDENCE + WHAT I DIDN'T TEST` (the negative space, mirroring explorer's "report what ISN'T there") · `5. CLEANUP` (scratch artifacts created and removed — makes Invariant #1 compliance auditable) · `6. RECOMMENDED NEXT` (options, never a decision — judgment stays with the orchestrator).
- **Packaging — a 5th agent in the existing bundle, not a new resident** (**derived**): RULES' Glossary defines a bundle as "a skill plus the agent definitions it requires," and ARCHITECTURE has no shape for a standalone agent. Ships as `plugins/repertoire/agents/spiker.md`; **minor** version bump to **1.1.0** per RULES §Versioning ("new or changed resident").

### Revision 2026-07-27 (b) — the `librarian` agent (6th bundle member)

_Forged 2026-07-27, immediately after the spiker. User-confirmed unless marked **derived**._

- **Why it exists — the bundle is stateless, the work is session-long.** Every agent is a cold spawn, every time. For the docs tree — a small, stable corpus re-consulted constantly — that's the wrong shape. _(Rejected: no agent, just a SKILL.md instruction to read PLAN's Features table — growing-docs' CLAUDE.md already mandates that, and it leaves the orchestrator spending its own context on the full tree with no incremental filtering, which is the actual value.)_
- **Distinct from `explorer` — the axis is stateless fan-out vs stateful singleton, not docs vs code.** These are structurally incompatible: explorer's design is "fire liberally, in parallel, one per narrow area", and parallelism cannot coexist with one agent accumulating what it has already delivered. Explorer stays haiku / stateless / cite-file:line for code; librarian is sonnet / singleton / incremental for docs. _(Rejected: merging into explorer — forces singleton discipline onto a fan-out agent and drags haiku, which already leaked past its budget once, into relevance work.)_
- **Corpus — growing-docs-native, general-docs fallback.** Fast-path knowledge of the layout: the PLAN Features table **is** the feature→doc index (never glob `docs/`), Current Focus → Start here, the code → `feature-*` → ARCHITECTURE/PLAN → README precedence chain, BACKLOG and CHECKPOINTS as separate corpora. Elsewhere it degrades to general documentation discovery (README, `docs/`, ADRs, CONTRIBUTING). Deliberately mirrors the house `## Ending` shape — native in an adopted host, graceful fallback outside. _(Rejected: growing-docs-only — dead weight in un-adopted repos, so the reuse habit the singleton depends on never forms. Rejected: docs + code-convention surfaces — re-blurs the explorer boundary that "keep distinct" just established.)_
- **Staleness — verify-before-cite, self-enforcing.** The librarian re-reads any file it is about to cite, every time, before answering. Staleness becomes *structurally impossible* rather than procedurally avoided — necessary because growing-docs Step 3 mandates doc writes mid-session. **Governing principle: correctness must never depend on the caller remembering to do something**, because a forgotten notification produces a silent, confident lie. _(Rejected: push-notification after every doc write — hinges on the orchestrator never forgetting across a long session, and fails without degrading. Rejected: staleness disclosure only — every answer arrives hedged, so the orchestrator re-reads anyway and the delegation dissolves.)_
- **Judgment boundary — reports what governs; never ranks, orders, or recommends.** It answers "what governs area X" and "what changed since I last told you", then stops. This works *because* growing-docs makes relevance mechanical — the Features table is the index, so the librarian performs a lookup, not a judgment. Keeps the bundle's core doctrine (the orchestrator never delegates judgment) intact. _(Rejected: recommending a reading order — relevance ranking IS the judgment about what matters, delegated to an agent that can't see the conversation. Rejected: flagging contradictions à la explorer's FLAGS — judging what counts as a contradiction is interpretation, and the precedence chain often resolves apparent conflicts the librarian can't see.)_
- **Delivery — `NEW` (full) / `ALREADY SENT` (pointers, re-send on request) / `NOT FOUND`.** New material in full; previously-delivered material named one line each rather than re-dumped; NOT FOUND names what it looked for, mirroring explorer. **The ALREADY SENT block is not politeness — it's compaction insurance:** the orchestrator's window may have been summarized since delivery, so it must be able to see *what* it was given and re-request it. _(Rejected: new-material-only — a compacted orchestrator gets a silent gap, same failure class as silent staleness. Rejected: full digest every time — discards the incremental delivery that justified a singleton over just firing an explorer at the docs.)_
- **Lifecycle — eager in a growing-docs host, lazy elsewhere; singleton enforced by a dedicated skill section.** Where `docs/PLAN.md` exists, dispatch once at session open with a broad brief-me query (justified: Step 3 means the session will touch docs). Elsewhere, spawn on first real need. The skill states the rule plainly — spawn once, thereafter always `SendMessage` the same agent; **writing a second `Agent` call for a librarian is the bug.** _(Rejected: always-lazy — loses the session-opening brief where a cold orchestrator gains most, and an easy-to-skip agent gets skipped. Rejected: always-eager — burns a spawn in un-adopted repos and trains the habit of ignoring its output.)_
- **Model — `sonnet`, read-only tools** (**derived**; tier user-stated in the pitch): relevance lookup sits above haiku (explorer's recorded leak is the evidence) and below opus. Tools `Read, Grep, Glob, Bash` like the other read-only agents. _(Gained `reasoningEffort: high` in the 2026-07-28 re-pin — see Roster.)_
- **No `## Ending`** (**derived**): it produces nothing durable. Notable as the **first resident that *consumes* the docs contract** rather than writing to it — every prior resident's growing-docs integration was an output ending; this is the inverse direction.
- **Name — `librarian`.** A reference librarian knows the collection and answers "what should I read for X" without doing your thinking. _(Rejected: `bookkeeper` — bookkeeping means recording, and this agent never writes. Rejected: `archivist` — also implies writing/custody.)_
- **Packaging** (**derived**): 6th agent in the same bundle, `plugins/repertoire/agents/librarian.md`; ships in the same **v1.1.0** as the spiker (one minor bump covers both, per RULES §Versioning — "new or changed resident").

### Revision 2026-07-30 — investigation control + live-state safety

_Forged 2026-07-30 from the graduated BACKLOG entry (Setsuna-repo incident: a verification task hit a proxy auth failure; ~2h, five proposed-then-retracted causal theories, three concurrent probes against the user's one live credential — tripping their live session's auth banner twice — and no advisor consult; the user had to intervene). Orchestrate **was** active in that session (user-confirmed), so SKILL.md was in the room and failed to fire — a genuine trigger gap, not a loading gap. Design drew on an external advisor consult (GPT-5.6-sol, PEER) captured in the entry, plus two in-repo second-opinion passes (Opus 5, Fable 5). User-confirmed unless marked **derived**._

- **Framing — advisor-first: inline investigation stays legitimate, spiral triggers gate it.** The advisor's automatic triggers were all design-shaped (architecture, indecision, fix-loop cap, security, large plan), so a debugging spiral tripped none. New §5 triggers make the consult mandatory mid-investigation. _(Rejected — the Fable reframe: a §1 mid-flight re-triage rule routing "why is this failing?" to spiker, mirroring the runner's stop-and-report duty at SKILL.md:25. Real insight — the orchestrator is the only actor that can slide from doing into diagnosing ungated, and spirals emerge mid-flight rather than being mis-triaged — but user chose the advisor-first anchor; the reframe's machinery-reuse argument partially survives in the PROBES line below. Revisit if spiral consults keep concluding "should have been a spike from the start.")_
- **Spiral triggers — narrow retraction rule, not "any 2 falsifications."** On the same empirical question, consult before opening another diagnostic branch after either (a) retracting a conclusion previously reported as **established/confirmed/root-cause**, or (b) abandoning **two** branches without obtaining discriminating evidence. A hypothesis explicitly labeled tentative and cleanly refuted counts as progress, not spiraling. _(Rejected: triggering on any two falsifications — falsification is healthy debugging; penalizing it spawns advisors during competent work.)_
- **Probe budget — binds both venues.** Inline (§5): ≤3 discriminating probes per empirical question, each stating in advance which outcomes support/refute which theory; exhaustion → advisor consult or INCONCLUSIVE, never a 4th probe. Spike brief (§2): gains an optional `PROBES:` line (default 3) beside `BUDGET:` — a probe is a semantic unit, a tool call is mechanical; they compose. _(Rejected: inline-only — a delegated spiral inherits no probe discipline, and a spiker could burn its 30 calls on six undisciplined theories. Rejected: raw time/tool-call budgets as the spiral signal — reading code is many calls, elapsed time is runtime-dependent; kept only as the spiker's existing mechanical leash.)_
- **Hypothesis ledger — starts at the 2nd causal theory,** backfilling the first. Row: CLAIM / EVIDENCE-FOR / FALSIFIER / RESULT / LIVE-STATE-TOUCHED. Every advisor consult and user report about the investigation quotes the ledger, not memory of it. _(Rejected: ledger-at-consult-time — reconstructed from an already-anchored context, which re-inherits the anchor it exists to break. Rejected: always-ledger — punishes the 5-minute fix with paperwork; the entry's own over-triggering risk.)_
- **Spiral consult = DECISION BRIEF variant, not a third brief shape.** The ledger replaces "options considered"; the QUESTION is fixed: *which assumption or layer am I failing to challenge; does the proposed next experiment discriminate among surviving explanations; should this stop as INCONCLUSIVE?* Never "find the bug" — a read-only fresh-context advisor can't reproduce, and handed only the favored theory it inherits the anchor. _(Rejected: a dedicated INVESTIGATION BRIEF — ~90% the DECISION BRIEF with the ledger swapped in; two contracts sharing one job is the E2E-tester smell.)_
- **Live-state safety — split by shape (the entry's own advisor drew the line: an advisor can challenge reasoning but cannot authorize spending quota or perturbing a live session).** The operation-shaped half → **CLAUDE.md Invariant #3**: *never fan out concurrent probes against a single live shared credential, session, or quota pool — single-flight, in any context.* Always-on, mechanically checkable, survives motivated mid-spiral reasoning, protects non-orchestrate sessions too. The judgment-shaped half → SKILL.md: before a **second consequential touch** of live state, say what the first established, what the next uniquely discriminates, its user-visible/state/quota effect — and if it can mutate state, spend quota, or disturb a live session, **get the user's consent**; the advisor may judge information value but is never a substitute for consent. "Consequential" defined operationally (mutation, user-visible effects, scarce quota, shared credentials, running sessions, process/resource contention) so it doesn't block harmless log reads. _(Rejected: both halves → Invariants — the consent half needs interpretation, exactly where a spiraling agent slips through, and invariants have no room for the operational definitions. Rejected: both halves → SKILL.md only — the harm class isn't orchestrate-specific, and the incident's live-session disruption is precisely the "one incident qualifies a rule" bar.)_
- **Advisor SCOPE widened** (**derived** from the entry): §5 + `advisor.md`'s description explicitly name investigation strategy, evidence-quality review, diagnostic dead-ends, repeated causal reversals, and whether to stop as inconclusive. The old "plans/architecture/deadlocks" framing is *why* the incident was filed as out-of-scope.
- **Classifier-block fallback is normative** (**derived** from the entry): if the spawn classifier blocks the advisor, that is **not** permission to continue — write the ledger, mark the cause unresolved, ask the user. Matches the recorded 2026-07-28 observation that the classifier blocks headless spawns intermittently.
- **Packaging** (**derived**): changed resident → minor bump to **1.3.0** per RULES §Versioning. Files: `SKILL.md` (§2 PROBES line, §5 spiral triggers + ledger + consult variant + live-state gate), `agents/advisor.md` (description), `CLAUDE.md` (Invariant #3), README row unchanged (composition unchanged — no count sweep needed).
- **Revisit trigger** (from the external advisor's would-change-my-mind, kept verbatim in spirit): loosen the retraction+probe triggers if ~10–20 real investigations show they mostly interrupt clean hypothesis elimination without changing the next step, or if consults at those gates consistently fail to redirect; loosen the live-state stop only if the resource is proven isolated, side-effect-free, and non-quota-bearing. **Watch for gaming:** repeated "likely" claims with no ledger is the early signal of relabeling-to-dodge-the-trigger.

## Gotchas

- **The override-refusal path is still unobserved** (see Spike findings) — GREEN covers brief discipline, verbatim relay, and factual-vs-judgment separation only.
- ~~The advisor flagged an **unspecified middle case in the house Ending convention**~~ — **RESOLVED 2026-07-27** in the spiker forge (debug-to-gotcha, its predicted venue, was shelved instead). A growing-docs host that lacks the relevant feature doc now falls back to a **dated entry in `docs/BACKLOG.md`** — a homeless finding is un-triaged knowledge, which is that file's stated purpose. The convention's "exactly two bullets" rule **survived its first flex test**: the chain lives *inside* the docs-ending bullet rather than earning a third one. Generalized to all residents in RULES §Ending.
- Cheap-model leash (from validation): explorer got its <150-line report cap + ~15-call tool budget after haiku leaked (3× cap overflow; 8-min/42-call sweep despite "sample a few"). Escalation order if leaks persist: harder wording → tool budget → model bump.
- Loop cap is 2 fix rounds; on deadlock the orchestrator takes over or sends the dispute to advisor arbitration — never a third round.
- **A spiker that launches its own background work can stall out without ever reporting** (observed 2026-07-28, first occurrence). The agent spawned a background diagnostic run plus a readiness monitor, then stopped to wait for them — but a subagent with no *live* children is considered finished, so nothing was going to wake it. It returned "waiting for the background run to report back" in place of a verdict, and the spike only completed because the orchestrator noticed the non-report and re-sent it with instructions to poll its own output files directly instead of awaiting a notification. **Failure mode to watch: a stall is easy to misread as a finding**, because what comes back is prose, not an error. Rule of thumb for the orchestrator: a spiker reply lacking a VERDICT line is a stall, not a result — resume it, don't interpret it. Consider folding "poll your background children's output directly; never block on a notification" into `spiker.md` if it recurs.
- **Frontmatter and the spawn-time override are two different surfaces with different value domains.** Frontmatter `model:` accepts full version-shaped names (`claude-opus-4-8` resolves and runs); the Agent tool's spawn-time `model` override accepts **aliases only** — `sonnet`, `opus`, `haiku`, `fable`. And the override has **no effort parameter at all**. Consequence, and it is easy to get backwards: *model pins are soft, effort pins are hard.* A wrong model is correctable mid-session; a wrong effort is only fixable by editing the file. This killed a plan to ship `opus` as the spiker default and express `claude-opus-4-8` as a per-brief override — that override is not expressible. Verify a value's domain against the surface you're actually writing to.
- **`--permission-mode bypassPermissions` is refused outright by the auto-mode classifier** ("Blocked by classifier", immediate — not a hang), so a spiker driving a headless `claude -p` harness cannot reach for it. The working shape is `acceptEdits` plus a scoped `--allowedTools` list (proven 2026-07-28). Worth knowing before a future spike burns its time-box rediscovering it.
- **A bundle's agent count is restated in ~7 places; changing composition misses most of them.** v1.1.0 (33a7a30) went from 4 agents to 6 and shipped stale counts in ARCHITECTURE's tree comment and Bundles list, RULES' README-table example and Glossary, and this doc's title and Description — caught only by an advisor consult, after the push. Root cause: CLAUDE.md Step 3 asks "does this doc need updating?" per *doc*, but a composition change is a fact restated across docs, so per-doc review kept answering "no." Rule promoted to RULES §Composition changes: grep the old count in the same change. Historical statements (changelogs, dated forge records, checkpoint entries) are *not* part of that sweep — they describe a past state and stay true.
- **A `: ` in an unquoted frontmatter `description` silently drops the WHOLE frontmatter block** (hit 2026-07-27 while widening the skill's description to mention the new agents — "cheaper workers: repo browsing…"). YAML reads it as a nested mapping. The runtime consequence is the dangerous part, spelled out by the validator: the skill loads with *empty metadata*, so `disable-model-invocation: true` disappears and a deliberately user-invoked skill becomes model-invocable — with no visible error anywhere. Caught only because `claude plugin validate` ran before commit. Rule promoted to RULES §Frontmatter YAML; use parentheses or an em dash instead.
- **Librarian singleton vs orchestrator compaction (designed 2026-07-27, unobserved):** if the orchestrator's context is compacted it may lose the librarian's agent reference and spawn a fresh one. This **degrades gracefully rather than breaking** — a new librarian re-reads and re-delivers, losing only incrementality (it will re-send as NEW what the old one had marked ALREADY SENT). Accepted as the failure mode, since the alternative was making correctness depend on the caller's memory, which the staleness decision explicitly rejects. Watch whether respawns are frequent enough to matter in practice.
