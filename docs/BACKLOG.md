## 2026-07-30 — advisor should catch debugging spirals, not just design calls

_Motivated by a real incident in the Setsuna repo (2026-07-30): a verification task hit a proxy auth failure and the orchestrator spent ~2h proposing+retracting FIVE causal theories, escalated a single-probe question into THREE concurrent probes against the user's ONE live shared credential (tripping the app's auth-failure banner on the user's live session twice), and never consulted the advisor — the user had to step in with "you're going in circles and overclaiming." Drew on a GPT-5.6-sol advisor consult (PEER mode); the advisor reshaped the initial lean materially, below._

**The gap (reframed by the advisor):** the advisor's automatic triggers (SKILL.md §5, ~lines 75–79) are all design/judgment-shaped — architecture, indecision, fix-loop cap, security, large plan — so a debugging/investigation spiral trips none. But this is **not only** an advisor-trigger gap: it's also an **investigation-control + live-state safety** gap. An advisor can challenge reasoning; it **cannot** authorize spending quota, perturbing a live session, or fanning out traffic against one credential. So live-state protection must be a hard stop + user consent, not merely "another reason to ask an advisor."

**Proposed changes (to `/forge`):**
- **Broaden advisor SCOPE wording** (SKILL.md §5 + `agents/advisor.md`) to explicitly name *investigation strategy, evidence-quality review, diagnostic dead-ends, repeated causal reversals, and whether to stop as inconclusive*. The current "plans/architecture/deadlocks" framing is *why* the orchestrator filed the incident as out-of-scope.
- **Retraction trigger — narrow, not "any 2 falsifications"** (falsification is healthy debugging; penalizing it would spawn advisors during competent work): _"On the same empirical question, consult before another diagnostic branch after either (a) retracting a conclusion previously reported as **established/confirmed/root-cause**, or (b) abandoning **two** branches without obtaining discriminating evidence."_ A hypothesis explicitly labeled tentative and cleanly refuted does **not** count.
- **Live-state = mechanical safety stop, advisor optional:** (i) shared/live diagnostic resources are **single-flight** — never fan out concurrent probes against one credential, live session, mutable user store, or quota pool; (ii) before a **second consequential touch**, state what the first established, what the next uniquely discriminates, its user-visible/state/quota effect, and why isolated evidence can't answer — and if it can mutate state, spend quota, or disturb a live session, **get the user's consent**. The advisor can judge the experiment's information value but is not a substitute for consent.
- **Drop the raw tool-call/time budget** (poor signal: reading code is many calls, elapsed time is runtime-dependent, the spiker already has a ceiling). Replace with a **per-question probe budget** (default ≤3 discriminating experiments; each states in advance which outcomes support/refute which theory; exhaustion → consult **or** report INCONCLUSIVE, never invent a 4th).
- **Classifier-block fallback is NORMATIVE:** if the intermittent classifier blocks the advisor spawn, that is **not** permission to continue — write the evidence ledger, mark the cause unresolved, and ask the user.
- **Spiral brief carries a hypothesis LEDGER** (claim / evidence-for / falsifier / result / live-state-already-touched) and asks _"which assumption or layer am I failing to challenge; does the proposed next experiment discriminate among surviving explanations; should this stop as inconclusive?"_ — **not** "find the bug" (a read-only fresh-context advisor can't reproduce, and given only the latest favored theory it will inherit the anchor).

**Revisit trigger (advisor's would-change-my-mind):** drop/loosen the mechanical retraction+probe triggers if measured use across ~10–20 real investigations shows they mostly interrupt clean hypothesis elimination without changing the next step, or if consults at those gates consistently fail to redirect; loosen the live-state stop only if the resource is proven isolated, side-effect-free, and non-quota-bearing.

**Risks to design against:** semantic gaming (relabeling conclusions "tentative" or splitting one question to reset the counter — early signal: repeated "likely" claims with no ledger); over-triggering clean debugging (watch whether each abandoned branch still produced discriminating evidence — if so it's progress, not circling); advisor blockage (the stop/inconclusive fallback must be normative); advisor context starvation (require the rejected-hypothesis ledger + exact evidence locations in the brief, or a fresh advisor inherits the anchoring); live-state ambiguity (define operationally around mutation, user-visible effects, scarce quota, shared credentials, running sessions, and shared process/resource contention — not so broad it blocks harmless log reads).

**Second-opinion pass (this repo's own orchestrator, 2026-07-30) — the external advisor lacked this repo's decision history; two things it couldn't have caught:**

1. **Possible reframe: this may be a §1 triage failure before it's an advisor-scope gap.** `SKILL.md:15,20` already route "uncertain about what's true" to `spiker`, not to inline investigation — logged 2026-07-27 as a decided split (ambiguity-of-intent vs. uncertainty-of-fact). "Why is this failing?" is the example given for spiker in that very line. Spiker's brief contract already carries a `BUDGET` ceiling and an `EXIT CONDITION` (`SKILL.md:41-43`), and its report format already distinguishes GREEN/RED/**INCONCLUSIVE** without collapsing the last into the second. If the five-theory spiral happened *inline in the main loop* rather than inside a spike, the more parsimonious fix may be strengthening §1 so this class of work can't happen outside spiker at all — extending spiker's existing BUDGET/EXIT-CONDITION/report-format with the retraction trigger and probe-count idea below, rather than building a parallel ledger/budget system on the orchestrator or advisor that duplicates what spiker already does. **Unresolved — user wants both framings (this one, and the entry's own advisor-first framing) surfaced to `/forge` rather than pre-decided.**
2. **The live-state single-flight + consent-before-second-touch rule is a genuine Invariants-list candidate**, not just SKILL.md doctrine — it's orthogonal to the advisor question entirely (governs spiker's conduct, or the orchestrator's, regardless of whether either consults advisor), and CLAUDE.md's own admission bar is "one incident of that class qualifies a rule." **User wants it raised at forge time** against the bar (operation-shaped absolute, guards irreversible/real-world harm) — candidate phrasing: *"Never run concurrent probes against a single live shared credential, session, or quota pool — single-flight only, and get explicit consent before a second consequential touch."* If it clears the bar, the hard cap is 10 and something existing may need to be evicted or this promoted alongside a review of the current list.
